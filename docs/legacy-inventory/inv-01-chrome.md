## 7. Gotchas / must-preserve

1. **Navbar is 42px, sticky, z 9999**; the modal layer (`.modal top:42px; height calc(100vh - 42px)`), the sidebar and its backdrop (`top 42px`) all assume it. Modals therefore centre in the area BELOW the bar, not the whole viewport.
2. **Map route layout**: on `/` the `Container.app-container` is `position: fixed; inset 0; overflow hidden; flex column; paddingBottom env(safe-area-inset-bottom)` and `.app-main` has `overflow hidden`; every other route is `height auto; minHeight 100dvh; overflow visible` with `.app-main overflow auto`. Header hidden on `/reset-password`. Banner hidden on auth pages.
3. `html { overflow-y: scroll }` permanently reserves a scrollbar gutter and `body.modal-open { padding-right: 0 !important }` — done to stop the sticky navbar shifting when a Bootstrap modal opens. Replicate (or ensure the new modal impl doesn't add body padding).
4. Viewport meta has `maximum-scale=1` (no pinch zoom) and `viewport-fit=cover`; `100dvh` used for compact modals (`compact-fit-modal`, `sa-lg-modal`) so they fit above mobile keyboards/toolbars.
5. **Dropdown menus must render below the bar**: custom popper offset + `flip: false`; search input sticky at top inside a scrollable 300px (180px mobile) menu; search inputs are UNCONTROLLED with 300 ms debounce and are cleared/refocused 50 ms after open; opening one closes others and the sidebar.
6. The navbar dropdown CSS is defined twice (navbar.css then dropdown.css) with partly different values — the effective values are the dropdown.css ones (listed in 1.5); don't copy navbar.css's `0.8rem/60px/120px`.
7. **`.modern-modal-compact .modal-header { padding: 10px 14px !important }` and `.modal-title { font-size: 0.85rem !important }`** silently override the inline header styles of every compact modal — but only once `modal.css` has been loaded (lazy import). So the same modal can look slightly different depending on whether an admin/user-list page was visited first. Rebuild should pick one (the `!important` values are what admins normally see; plain users on the map typically see the inline `6px 12px / 0.95rem`). Same story for `.modal-footer .btn` (profile.css `6px 12px 0.85rem` vs modal.css `8px 16px 0.9rem`).
8. **Dead/never-rendered things** (safe to drop, but note if parity is judged by code): SearchableDropdown (+ broken CSS path), ToastContainer/useToast, SkeletonLoader, FloatingActionButton, Breadcrumb, TutorialWidget, Joyride `TutorialTour` component, EmailSetupModal (`needsEmail` forced false), NoticeBoxModal (setter never called), Profile "Change Password" button (sets unconsumed state), `.profile-status-indicator`, `.username`, `.sidebar-title/.offcanvas-header`, `.saved-layers-list/.layer-row/.btn-icon`, `.sync-progress-bar` (no CSS), `table.css`, `user-management.css`, `tempAccess.css`, `GoToLocationForm.css`, `ShiftPMTilesForm.css`, `form-fixes.css`, `formControlFixes.js`.

11. **Font Awesome 6 free + emoji** are the icon system (sidebar uses raw emoji in text, so rendering depends on the OS emoji font); `/profile-icon.png` is loaded from `public/`.
