### 1.2 Data loading (`loadStatistics`, on mount and refreshKey change, abortable)
Parallel:
1. `GET /stats` → `rawStats` ({ totalUsers, totalOnline, loginStats{last24h,last7d,last30d:{uniqueUsers}}, sessions[], tehsilStats[{_id,userCount,activeCount,inactiveCount}], dailyActivity[{date,activeUsers,sessions}], subscriptionHealth{active,expired,pending,expiringSoon}, registrationsDaily/Weekly/Monthly[{label,count,publicCount}] }).
2. `GET /online-users` → each entry enriched with `location` via `getIPGeolocation(ip)` = `GET /api/geo/ip-lookup?ip=` (fallback `{city:'Unknown',region:'Unknown',country:'Pakistan',lat:0,lon:0}`). Done with `Promise.all` per user (N requests!).
3. `GET /subscription-stats` (optional, `.catch(()=>({data:null}))`) → `{ recentRenewals[], totalRevenue{total,direct,fromSubAdmins} }`.
4. `GET /multi-device-users` (optional) → array of users with `ipCount`, `ipAddresses`, `lastActive`, `subscriptionType`, `userName`, `userId`, `tehsil`.
Then `setLastUpdated(new Date())`. Errors: `err.response.data.error || err.message || 'Failed to load statistics'`; cancel errors ignored.

Note paths `/stats`, `/online-users`, `/subscription-stats`, `/multi-device-users`, `/user-ip-history/:id` have NO `/api` prefix; `/api/geo/ip-lookup` does.

### 1.3 Derived data (useMemo) — must be reproduced exactly
- `dailyActivity[i].rollingAvg` = mean of `activeUsers` over window `[max(0,i-6)..i]`, `toFixed(1)` parsed.
- `tehsilStats._id` trimmed, empty → `'Unknown'`.
- `multiIPAnalysis`: source = `multiDeviceUsers` if array else `onlineUsers`; keep `ipCount > 1`; `riskLevel` = `ipCount>5?'high': ipCount>3?'medium':'low'`; sort desc by ipCount; summary `{totalUsers, highRisk, mediumRisk, lowRisk, totalExtraIPs = Σ max(0, ipCount-1)}`.
- `periodUsers` (Activity tab): cutoff by `selectedPeriod` ∈ `last24h|last7d|last30d` (24h/7d/30d ms); group sessions by userId → `{userId,userName,tehsil,subscriptionType,lastLogin (max start),sessionCount}`; sort lastLogin desc.
- `renewalAnalysis` (Renewals tab): rows = `subscriptionData.recentRenewals`; `paidRenewals` = `!r.subAdminPayment && subscriptionType not in ['trial','free'] (case-insens.)`; `subAdminPayments` = `r.subAdminPayment`. `withinDays(d)`, `paymentsWithin(d)`, `priorPeriod(d)` (window `[now-2d, now-d)`), `paymentsPrior(d)`. `sumFee(list)` = Σ (`r.bySubAdmin ? (r.fee||0) : (r.fee||1000)`) — **old direct renewals with no fee assume Rs 1000**. `sumPaid` = Σ fee||0. `revenueXd = sumFee(renewalsXd) + sumPaid(paymentsWithin(X))` for X ∈ 7,30,90,180. `pctChange(cur,prev)` = `!prev ? (cur>0?100:0) : round((cur-prev)/prev*100)`. `dailyRenewals = bucketRenewalsByGranularity([...withinDays(rangeDays), ...paymentsWithin(rangeDays)], granularity)` where `{rangeDays,granularity} = getRenewalViewConfig(renewalView)`.
- `hourlyActivity`: 24 slots ending at current hour (`d.setMinutes(0,0,0)`), label `HH:00`; a session (start, end||now) counted in every slot it overlaps (`start < slotEnd && end > slotStart`); `users` = distinct userIds, `sessions` = count.

## 3. Sub-admin domain model (what the rebuild must understand)

- A **sub-admin** (`userType==='subadmin'`) is a reseller appointed by the admin: they create/renew/manage their own customers (regular `user` accounts tagged with an owner), within a **territory** (list of tehsil names, may overlap others). Admin appoints by creating a new account (activation email sent) or promoting an existing user.
- **Status machine** (`subAdmin.status`): `awaiting_activation` → (activates via `/subadmin/activate/:token`, accepting the Fair Charge Policy and entering their own payment numbers) → `active` → (overdue bills ≥ `unpaidThreshold` Rs) → `final_warning` (deadline = `finalWarningHours`, shown as `finalWarning.deadline`) → `suspended_unpaid` (writes blocked; admin can "Restore now") ; admin may `disabled`/`enable` at any time (disable logs them out, customers unaffected).
- **Billing**: every billable event (customer activation, renewal, upgrade, adjustment) creates a **bill line** with `platformPrice` (what the platform charges the sub-admin, from the pricing tiers by mouza count or negotiated `priceOverride`, or the price the sub-admin typed in `customerFee`) and is grouped into a **daily bill** (`day`, `total`, `paidAmount`, `unpaid`, `dueAt = day + paymentWindowDays`, `overdue`). The sub-admin pays the admin (JazzCash/EasyPaisa/bank/cash); admin records **payments** (optionally with proof), can edit (with reason, history kept), reverse (negative payment linked by `reversesPaymentId`), or **correct balance** (adds an adjustment line `BALANCE_ADJUSTED`). Position = `balance` (owed), `overdue`, `dueNotOverdue`, `paidTotal`, `advanceCredit` (overpayment).
- **Trials**: plan `Trial24` = free 24-hour trial, max `trialMaxMouzas` mouzas, not billed, once per customer, counts against `trialQuotaPerMonth`.
- **Plans allowed** per sub-admin: subset of `Trial24`, `Monthly`, `Yearly` (`PLAN_LABEL`: `Trial24 "24-hour trial"`).
- **Requests** (sub-admin → admin): `kind` ∈ `more_mouzas` (raise a customer's mouza limit; approval sets `mouzaLimit` + optional `monthlyPrice`), `assignment_change`/others with `requestedAssignment[{tehsil,mouzas[]}]`, and correction requests referencing an `event`. Statuses `pending|approved|rejected`, admin `decisionNote` shown to sub-admin.
- **Customer activation**: creating a customer sends an email with `/activate/:token`; the customer presses "Activate account" (POST) — plan starts at activation, and that's when the sub-admin is billed.
- **Payment details**: each sub-admin's own JazzCash/EasyPaisa/phone/WhatsApp are shown to *their* customers for renewals; admin can lock them. Admin's own details are shown to direct customers and on sub-admin bills.
- **AKAR**: tehsil named exactly `AKAR-Cholistan` is admin-only; `withoutAkar()` strips it from sub-admin tehsil lists.

## 16. Gotchas / fragile behaviours to preserve
1. **API path inconsistency**: stats endpoints are `/stats`, `/online-users`, `/subscription-stats`, `/multi-device-users`, `/user-ip-history/:id`, `/stats/visitors` (no `/api`), while everything else is `/api/...`. Keep both forms.
2. **Online users geolocation fan-out**: one `/api/geo/ip-lookup` request per online user (and per IP in the IP modal), awaited with `Promise.all` before the page renders.
3. `renewalAnalysis` assumes **Rs 1000** for direct renewals without a `fee`, and "Revenue at Risk (7d)" = expiringSoon × 1000.
4. Renewal view option implies granularity (7d/30d daily, 90d weekly, 180d monthly); average line = total / (rangeDays / {1,7,30}) counting empty buckets; label pill width = `len*6+12`.
5. `bucketRenewalsByGranularity` keys: daily uses `toISOString()` (UTC) while sub-admin PerformancePanel uses **Pakistan time (+5h)** — two different day boundaries on the same page. Weekly label format `W23 '26` vs Performance `Wk 09 Jun`.
6. Legend checkboxes: Overview/24h/Renewals use `hide` prop (series stays in recharts legend payload); Registrations/Performance/Tehsil render series conditionally with a hand-built legend. Visibility defaults: overview `{activeUsers:true, rollingAvg:true, sessions:false}`, online `{users:true, sessions:false}`, renewals `{count,revenue:true}`, multi-IP radio default `ips`.
7. `multiIPAnalysis` falls back to online users when `/multi-device-users` fails — tab count silently changes meaning.
8. Tehsil hotspot chart: horizontal scroll container, width `max(640, n*36+60)`, bars sorted by *shown* total so toggling Active/Inactive re-orders tehsils; label is drawn on the inactive bar when both are visible.
9. Activity period cards: selected state visible via `#e0f2fe` background + `text-primary` (statistics.css kills `.border-primary` borders with `!important`).
10. `.badge.bg-secondary` inside statistics containers is `rgba(255,255,255,0.2)` on white (session count pills look faint); alert text colours are pastel (`#fca5a5` etc.) on light backgrounds. Replicate rather than "fix" if pixel-identical is required.
11. `customStyles` is injected via `<style>` on three pages and globally forces recharts text to `#1a1a1a`; `chartTooltipAutoHide` (installed app-wide) closes touch tooltips after 3 s, on outside tap, and on scroll by dispatching synthetic `mouseout` on `.recharts-wrapper`.
12. Sub-admin list row tint uses CSS var `--bs-table-bg` on the `<tr>` plus solid colour + 4px left border on the sticky first cell; `FREEZE_TH` bg `#e2e8f0` corner.
13. Duplicate-payment guard: server returns **409 `{duplicate:true, message}`**; UI confirms "Record anyway" and re-posts with `confirmDuplicate:true`. Proof upload happens *after* the payment is created and failure only annotates the success message.
14. `ExistingUserPicker` auto-selects when the search yields exactly one user; users API capped at 100 rows.
15. Disable sub-admin prompt is not `required` (empty reason allowed, cancel = null); restore/reverse prompts are required.
16. DetailModal tabs are a `Nav` (not `Tabs`) inside a fixed-height body `calc(100vh - 150px)`; Performance stats fetched lazily once; Activity/Customers debounced 300 ms; events table dims to opacity .6 while loading.
17. `AppointModal` success hides the submit button and shows the generated password in `<code>`; `onDone` reloads list immediately (before closing).
18. Sub-admin dashboard polling: Bills tab 30 s + window focus; Online tab 60 s; both cleared on tab change. Error on initial load replaces the whole page.
19. `RenewModal` in SubAdminUsers is unreachable (no `setRenewUser` call); renewals are done through `UserEditForm`. `?new=1` opens Create modal only on first mount; `?edit=` likewise.
